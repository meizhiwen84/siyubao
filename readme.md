--------新增权限功能的提示词----------
一、核心业务需求
权限控制：/chat-preview入口页面需卡密验证，用户必须先在卡密验证页面输入正确卡密，才能进入该页面，未验证直接访问需重定向到卡密页；
卡密管理：提供卡密配置页面，支持配置卡密的总使用次数、剩余使用次数，且支持开启 / 停用卡密（停用后无法验证通过）；
次数扣减：进入/chat-preview页面后，点击平台接入按钮调用/generateDyChat接口，请求成功后原子操作扣减该卡密剩余使用次数；若剩余次数为 0，前端立即弹出提示：“剩余使用次数不足，请联系业务人员”，且禁止后续接口调用。
二、技术栈与架构约束
后端：SpringBoot+MVC，所有请求经 Controller 层处理，禁止使用前后端分离框架，视图返回纯 HTML；
前端：纯 HTML+JS+CSS，无 Vue/React 等框架，前端交互用原生 JS 实现，弹窗用原生 JS 或简易模态框（无需复杂插件）；
数据存储：使用 h2 数据库存储卡密信息，需设计合理表结构；
会话管理：卡密验证成功后，通过HttpSession存储用户当前有效卡密，供后续接口扣减次数使用，会话失效后需重新验证；
关键要求：剩余次数扣减必须是原子操作，防止并发调用导致次数扣减错误；卡密验证、次数扣减需做服务端二次校验，禁止仅前端校验。
三、需完整开发的功能模块（含前后端）
数据库层：设计卡密表，包含必要字段，提供建表 SQL；
实体层：创建卡密对应的 Java 实体类（Entity）；
持久层：基于现有jpa实现卡密的增删改查、原子扣减次数、验证卡密有效性（状态 + 剩余次数）；
服务层：封装卡密核心业务逻辑（验证、配置、原子扣减），处理业务异常；
控制层（Controller）：
卡密验证页面、配置页面、/chat-preview页面的视图跳转接口；
卡密验证接口（接收前端卡密，验证通过后存入 Session）；
卡密配置接口（新增 / 编辑 / 启用 / 停用卡密，修改使用次数）；
核心接口/generateDyChat：增强逻辑，先校验 Session 中卡密有效性（未过期、未停用、剩余次数 > 0），请求成功后原子扣减次数，若校验失败直接返回错误信息；
前端页面：
卡密验证页面（输入框 + 提交按钮，验证失败提示错误信息）；
卡密配置页面（卡密列表、新增 / 编辑表单、启用 / 停用按钮，支持分页）；
改造/chat-preview页面：增加 Session 卡密校验（无有效卡密则重定向），点击 “平台接入” 按钮时，先请求/generateDyChat，根据返回结果处理（成功则正常执行业务，失败则弹出次数不足提示，禁用按钮）；
异常处理：统一处理卡密不存在、已停用、次数不足、未验证直接访问等异常，返回友好的前端提示信息；
拦截器：实现一个拦截器，对/chat-preview和/generateDyChat接口做统一拦截，校验 HttpSession 中是否有有效卡密，无则重定向到卡密验证页面。
四、开发要求
代码规范：符合 SpringBoot 开发规范，类、方法、变量命名清晰，添加必要注释；
可集成性：所有代码按模块划分，配置类（如拦截器配置、MyBatis 配置）独立，可直接复制到现有项目中，仅需少量配置（如数据库连接）即可运行；
原子扣减实现：明确使用MySQL 行锁或MyBatis-Plus 乐观锁实现剩余次数的原子扣减，保证并发安全；
前端交互：原生 JS 实现，无第三方框架依赖，弹窗样式简洁通用，按钮状态随业务逻辑动态变化（如次数不足时禁用 “平台接入”）；
测试友好：核心接口（卡密验证、扣减次数、配置）提供清晰的入参出参说明，方便联调测试；
配置简洁：尽量减少配置项，核心配置（如拦截器、视图解析器）提供完整代码，无需手动修改现有配置。
